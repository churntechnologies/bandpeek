# Proposed macOS accuracy contract — Milestone 2

BandPeek reports **observed TCP/UDP socket bytes by process since this monitoring session's baseline**. It samples one persistent Apple `nettop` collector every five seconds. These are best-effort observations, not a complete ledger of traffic.

- **Bytes:** `nettop`'s cumulative `bytes_in`/`bytes_out`, converted into nonnegative session increments. Controlled plain TCP tests match socket payload sizes; HTTPS also includes protocol/encryption data beyond the downloaded file. These are socket-level counters, **not Ethernet/Wi-Fi wire bytes**, packet-capture totals, or ISP billing totals. Retransmission, link, tunnel, and protocol accounting must not be advertised as exact.
- **Scope:** the supported product scope is **All interfaces (includes local traffic)**. LAN, loopback and any tunnel traffic exposed by `nettop` are included. Both local socket endpoints can appear, so summing processes can count one local transfer at both ends. `nettop` can classify tested sockets as Wi-Fi versus loopback, but Wi-Fi includes both LAN and internet traffic. Ethernet and VPN mapping across interface changes are not established. No Wi-Fi/Ethernet history selector is supported by this collector yet.
- **Identity and loss:** process identity is PID plus verified process birth time. Unverifiable exited rows are omitted; a retained terminal row is not sufficient evidence of identity. Immediate-exit transfers can be lost entirely at one-, two-, and five-second sampling. The controlled churn percentages in the milestone report describe that workload, not an expected loss rate for every Mac. Process exit tails, resets and missing samples can also lose bytes.
- **Start, sleep and recovery:** pre-existing processes and the first complete frame of each collector generation establish baselines. Session totals remain monotonic within the running app. A collector failure or a header gap exceeding four sample intervals triggers a visible gap and a new generation; totals are retained and counters rebaselined. The gap clock includes sleep. Rates use actual sleep-inclusive sample spacing. Traffic during a gap is unknown and is not reconstructed. This is not durable storage across app exits.
- **Comparison:** for the same verified live process, counter epoch, scope and completed samples, increments should agree with `nettop`. Independently timed streams, startup baselines, unresolved identities, terminal rows and restarts differ. There is no defensible universal ±percentage guarantee. Controlled long-lived transfers can match exactly while bursty processes are severely undercounted.
- **Must not claim:** total internet usage, accurate metered/billed data, complete lifetime/app/system usage, complete short-lived-process coverage, exact physical-interface or VPN totals, packet-level/wire accuracy, lossless sleep/outage accounting, or Today/Yesterday totals before a separately designed persistence policy exists.

Suggested user wording: **“Observed network activity · all interfaces, including local traffic. Some short-lived activity and traffic during monitoring gaps may be missed.”**

See [Milestone 2 evidence and limitations](milestone-2.md). The UI and README should use this contract only with the report's validation qualifications.
