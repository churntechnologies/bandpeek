# BandPeek 0.1.0-beta.3 candidate

Local candidate only. No tag or publication is authorized or performed.

- Fix permanent zero rates after ProtonVPN disconnect. The existing `nettop`
  stream can acquire a valid `kernel_task.0` row after teardown; it no longer
  causes all process counters in the same frame to be discarded. Kernel rows
  remain unattributed, preserving verified PID + process birth identities.
- Detect settled changes to IP interfaces, tunnel membership (`utun*`), link
  availability and primary IPv4/IPv6 paths. Debounce, kill/reap the old child,
  then start one new collector with fresh baselines. Keep session/history totals
  and avoid counting preexisting counters as new traffic.
- Ignore Wi-Fi peer-discovery changes and unchanged snapshots. Zero traffic
  never triggers recovery. Repeated malformed frames now recover like stream
  stalls instead of publishing zero indefinitely.
- Retain two-second sampling, rate notifications, buffered minute history,
  the cached popup and existing updater verification/install lifecycle.

See [beta.3 validation](../beta3-validation.md) for raw-source diagnosis,
reproduction commands, recovery times and validation scope. Existing macOS
best-effort socket accounting, short-lived-process and shared-helper attribution
limitations remain. Apple Silicon/macOS 13+, validated on macOS 27.

Publication remains subject to the existing exact-tag release policy. This task
does not authorize a tag, GitHub release, updater manifest publication, or install
over the user's application.
