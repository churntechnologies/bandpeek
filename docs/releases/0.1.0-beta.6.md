# BandPeek 0.1.0-beta.6

- **Settings ▸ Updates** is a new row with a **Check for Updates…** button and a
  line of status text, so the check is available inside the app and not only in
  the app menu. It shows checking, downloading, up to date, failed (try again)
  and, once a verified update is downloaded, **Restart to Update**. The app-menu
  item added in beta.5 shows the same state.
- A manual check within 30 seconds of the last one is ignored, and manual and
  scheduled checks share one gate, so they never overlap. The status changes to
  "checking" immediately.
- The web side of the app gets two parameterless commands for this (read the
  status, ask for a check). It cannot set update endpoints, read keys or control
  the install. Nothing new is sent anywhere.
- Retain everything from beta.5: the app-menu item, live per-app speeds,
  two-second sampling, the cached popup, topology recovery and the signed-update
  install lifecycle.

See [beta.6 validation](../beta6-validation.md) for the checks that were run and
what was not covered. Apple Silicon/macOS 13+, validated on macOS 27.

An approved unnotarized build is ad-hoc signed, not Apple Developer ID signed or
notarized. If macOS blocks first launch and you choose to trust this beta, use
**System Settings → Privacy & Security → Open Anyway**, then confirm **Open**.
Existing beta.5 installs update to this build automatically within about six
hours, or when BandPeek is quit and reopened.
