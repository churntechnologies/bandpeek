# BandPeek 0.1.0-beta.5

- **Check for Updates…** in the BandPeek app menu checks GitHub Releases right
  away instead of waiting for the six-hour schedule. The item's title shows
  what is happening: checking, downloading, up to date, or failed (click to try
  again). Once a verified update is downloaded it reads **Restart to Update**;
  clicking it closes the main window, which the install already waits for, and
  BandPeek relaunches into the menu bar.
- Manual and scheduled checks share one gate, so they never overlap, and a manual
  check within 30 seconds of the last one is ignored to stay well under GitHub's
  unauthenticated API limit. The item appears only in installed Apple Silicon
  app bundles and only while the main window is open (the menu bar of a
  menu-bar-only BandPeek is not shown by macOS).
- Retain everything from beta.4: live per-app speeds, two-second sampling, the
  cached popup, topology recovery and the signed-update install lifecycle. No
  updater command is exposed to JavaScript and nothing new is sent anywhere.

See [beta.5 validation](../beta5-validation.md) for the checks that were run and
what was not covered. Apple Silicon/macOS 13+, validated on macOS 27.

An approved unnotarized build is ad-hoc signed, not Apple Developer ID signed or
notarized. If macOS blocks first launch and you choose to trust this beta, use
**System Settings → Privacy & Security → Open Anyway**, then confirm **Open**.
Existing beta.4 installs update to this build automatically within about six
hours, or when BandPeek is quit and reopened.
